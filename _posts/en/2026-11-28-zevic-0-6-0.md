v0.6.0 is a big release that aims for **no border with C**.

C libraries have done more of the world's work than any others. For a language to be used, those libraries must be easy to use. Zevic could always call a C function with `extern "C"`, but you had to write each declaration by hand, and a function that takes a struct by value needed a thin bridge written in C (a shim).

0.6.0 removes that work.

## import C

```zevic
import C "sqlite3.h" as Sq strip "sqlite3_", "SQLITE_"

fn Main() {
    let v: CString = Sq.Libversion()
}
```

With this one line, clang reads the header, and the functions, structs, `enum`s and `#define` constants are there to use. The [sqlite package](https://github.com/zevic-lang/sqlite) dropped its 64 lines of C shim and now runs on `import C "sqlite3.h"` alone. When you want to edit the generated module by hand, `zevic bind` writes it to a file.

## Structs by value

Functions that pass `Vector2` and `Color` by value, as raylib does, are the part where the calling convention differs from one system to the next and is easy to get wrong by hand. Zevic leaves it to the C compiler. The compiler writes and compiles a small C function (a shim) that takes pointers, and shows you an ordinary function that takes and returns values.

```zevic
let s: Rl.Vector2 = Rl.Vector2Add(a, b)
Rl.ClearBackground(color)
```

The new guide, [Using C](/en/c/), covers it in detail. It also shows how to pass `Null` for a callback, and `Unsafe.CallbackAt` for function pointers whose number has a meaning, such as `SQLITE_TRANSIENT`.

## Writing an OS

`zevic --freestanding` builds with no runtime, no GC and no standard library. It is a mode for writing code that runs where there is nothing underneath, such as a kernel or firmware. You can pass `.S` assembly and `.c` files with it, and name the linker script and the entry symbol. You can also put `[freestanding]` in `zevic.toml` and build with `zevpm build`.

[examples/hello-os](https://github.com/zevic-lang/zevic/tree/main/examples/hello-os) is a kernel that only prints "Hello, World!" under RISC-V QEMU. It writes to the UART with the new `Unsafe.At` and `WriteVolatile`. Code that needs the runtime (`class`, `Array`, joining strings) is a compile error, not something that breaks at run time. The guide is [Writing an OS](/en/os/).

## Http moves into packages (breaking)

`Zevic.Http` is gone from the standard library. The client is the [curl package](https://github.com/zevic-lang/curl) (built on libcurl; HTTPS, redirects and proxies) and the server is the new [httpd package](https://github.com/zevic-lang/httpd). `Zevic.Net` (TCP and UDP) stays in the standard library.

Now that C libraries work through `import C`, the plan is to grow things better left to C, such as networking and compression, as packages, not to carry them in the standard library.

## What it cannot do yet

- variadic functions (such as `printf`) and macros that are more than a plain number or string cannot be bound yet
- a function that takes a callback and a struct by value together cannot be bound yet
- a freestanding library (`kind = "lib"`) cannot be made yet

What could not be bound is listed, with the reason, by `zevic bind`. See the [releases](/en/releases/) for the details.
