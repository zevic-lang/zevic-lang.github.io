v0.4.7 tidies up packages that use C libraries, and points HTTPS users to the right place.

In `[native]` of `zevic.toml`, the keys `lib_dirs`, `include_dirs` and `defines`, which the specification already listed, now work in zevpm. Before, it read only `libs` and gave an error for the others. A directory is either relative to the package that names it, or absolute. The keys written in dependencies are used as well.

When you give `Zevic.Http` an `https://` address, the error now points to the `Curl` package (`zevpm get zevic-lang/curl`). `Http` is for plain HTTP and needs no dependencies, so it has no TLS. HTTPS is the job of `Curl`, which builds on libcurl.

The `Curl` package is now tested on Windows in CI too.

See the [releases](/en/releases/) for details.
