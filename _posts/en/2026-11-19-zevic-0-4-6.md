v0.4.6 is mostly about better error messages.

When you get a name, a function or a module member wrong, the compiler now shows the closest name, as in `note: did you mean `Println`?`. If you write `null`, it explains that Zevic has no null and points to `Option` for a value that may be missing. Passing a number where a `String` is expected suggests string interpolation, `"${value}"`.

The error for a function that does not end with a value now points at the function's closing `}` instead of the opening `{`. When a string is not terminated, only that lexical error is reported; the parse errors that would follow from it are left out.

Every example under `examples/` is now a package of its own, with a `zevic.toml` and a `src/Main.zev`. Run `zevpm run` in an example's directory to build and run it. `06_c_interop` keeps its C file in `native/`.

See the [releases](/en/releases/) for details.
